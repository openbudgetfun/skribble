# Skribble documentation

Skribble serves Flutter developers building playful, hand-drawn apps. Its documentation should let developers read API guidance, copy prose or exact code, find every component, and try actual Wired widgets before using them in their own apps.

The existing Wired identity is binding: hand-lettered type, rough ink outlines, coloured marker fills and hatching. Gentle is the default. The user approved the restrained uneven fill overlap after comparing screenshots. Preserve that treatment.

Reading works on phones and desktops. Text must support ordinary selection and copying, including content beyond the viewport. Navigation and examples must support keyboard and accessibility actions. Scrolling must remain responsive on long articles. Decorative animation can be disabled and respects platform reduced motion.

The home example lets readers check a task, toggle a saved state, and replay ink without resetting those choices. These are local demonstration states, not a storage product or a promise of persistence across reloads. Motion examples teach the same standard Flutter animation APIs available to consumers.

Existing Markdown documents and routes remain the content source. The separately built storybook remains available for broader component exploration.
